# Local persistence and source input contract

Status: implementation-local engineering contract for the draft profile. It adds no wire object, hash/signature formula or legacy rule. Code is Apache-2.0; this document is CC-BY-4.0. Original OM World contributions and repository notices remain applicable.

## Operator setup and API

Configure a ledger path, pinned deployment/ledger public key and separate protected checkpoint directory with a stable storage_id. `CheckpointStore(directory, ledger_path, deployment, authority, storage_id)` rejects nested ledger/checkpoint directories and symlink targets. Sibling directories alone do **not** establish operational independence: the operator must protect the anchor from DB backup/restore and retain its newest version separately. Rolling back both together is undetectable here. This is local Unix `flock`, SQLite and filesystem persistence, not hardware monotonic storage, distributed atomicity or a key vault. The directory, source policy and local authority process are trusted. Private keys never belong in receipts/exports.

Call `initialize_empty(ledger)` once for a new empty ledger. It refuses an existing anchor or nonempty ledger. Normal startup uses existing storage; missing/corrupt/mismatched anchors fail closed rather than rebootstrap. `read()` verifies the signed prefix's authority/deployment. `advance(ledger)` audits the retained prefix and tables, obtains the current checkpoint in one transaction, then atomically writes the new envelope. Use `advance` after separately authorized consume/release operations too. All cooperating processes use the same anchor and anchor→ledger lock order. Direct lower-level ledger users can bypass this coordination and are trusted primitives, not this admission contract.

`persistent_admit(store, binder, request, index, ledger, anchors, receipts)` acquires the anchor lock, audits its prefix, authenticates source high waters, persists them, performs pre-call authorization, and checks current source/authorization expiry **inside the reserve write transaction after acquiring its lock**. It never executes an action. A refusal rolls back that reservation; authenticated source revisions already observed remain saved. In particular, cancellation revision 2 is retained even if it denies the request, so revision 1 cannot revive it. Same-revision different bytes, decreasing revision/as-of, wrong principal/schema/source, missing roles, inconsistent context times or history commitments refuse.

After DB commit it advances the independent anchor before returning a reserved result. Any failure at that advance returns `WAITING_ANCHOR_NO_ACTION`: no handoff, automatic retry of an action or automatic release. A retry reports existing recorded state, never fresh execution permission. A directory fsync failure may mean rename happened but durability is uncertain; treat it as unavailable/waiting and recover, not success. Before-replace failure leaves the old anchor bytes. Generation is local bookkeeping, not an independently verifiable antirollback counter.

## Source receipts and policy

`SourcePolicy(principal, schema_digest, status, history, clock, allow_synthetic=False)` pins three `Source(source_id, authority, max_age_seconds, evidence_kind='source_attestation')` values outside exports. Default local wall time is UTC from the operating system; that clock and its maintenance must actually be trusted. Test clocks can be injected only as engineering fixtures. This implementation supplies no synchronization, network acquisition or real-source adapter. A configured signature authenticates a claim's origin, not truth, source completeness or honest wall time.

Each receipt has exactly: format (`omworld.offline-source.v1`), role, source_id, authority, revision (nonnegative safe integer), principal, schema_digest, evidence_kind, as_of, issued_at, expires_at, payload, signature. Signature uses the existing Ed25519 signature-input helper excluding signature; this local receipt is not a new normative profile artifact. Revision is monotonic per configured role/source. UTC times obey as_of ≤ issued_at < expires_at; receipt age and expiry are checked against local wall time. No source snapshot is relabeled with a newer as_of. All three as_of values must match the operation context.

Role payloads are closed:

- status: active_intent_ids, an exact unique digest list asserted active by that source.
- history: identity_profile_digest and key_event_digests, binding the actual exported IdentityProfile and its complete event-reference set. A matching export is not independent proof that the source omitted no real revocation.
- clock: time_basis fixed to UTC-source-attestation. Its signature identifies the configured clock claimant; local wall time remains the expiry enforcement root.

The anchor envelope saves each full signed receipt, canonical digest and local validated_at separately from source as_of/issued_at. Source max-age is an explicit bounded-staleness policy, not real-time knowledge of later cancellations. Independently revalidate before any separately implemented future action handoff. Synthetic receipts require explicit synthetic source policy AND allow_synthetic=True; success is prefixed TEST_. Tests use deterministic synthetic keys and timestamps, never real production provenance. A caller dishonestly labeling synthetic bytes as real is outside the configured-source trust boundary and is not certified by signature verification.

## Recovery and acceptance

`recover(ledger)` validates the saved prefix against recovered DB/log/materialized state, advances only to the recovered current signed prefix, preserves source high waters and reports pending reservations as `RECOVERED_NO_ACTION`. It does not establish fresh source status, authorize actions, consume/release or adjudicate uncertain external outcomes. Fresh admission must authenticate current sources afterward. A DB restored below the retained prefix is rejected without lowering the anchor. Restore the complete legitimate DB/WAL/SQLite backup, not fabricated events. Do not copy a live DB without WAL or blindly overwrite the anchor from a DB export.

Acceptance covers restart/idempotency, explicit initialization, rollback refusal, source binding/signatures/expiry, cancellation and revision replay, atomic replacement failure, and DB-commit/anchor-write gap recovery without execution or release. Original 75 tests remain byte-identical. Added fixtures are synthetic engineering tests; original published RFC vectors and independent Node/OpenSSL cross-checks remain in the suite. These checks do not certify hardware/power-loss behavior, real source operation, tool outcomes, production deployment or scientific claims. Native attestation, distributed/multi-deployment budgets and existing unsupported capabilities remain unsupported. Issues #4–#8 remain open.
